    Operate / CLI

    agentos command reference

    agentos project is the administrator CLI for project lifecycle. It runs as root. Project agents cannot run it. The package installs it to /usr/sbin/agentos.

    agentos system is the client for hostd. The administrator and the system agent can use it.

    The command and service names are provisional.

    Commands#

    CommandResult
    agentos project create NAME [flags]Creates the identity, directories, and slice. Prints NAME.
    agentos project listPrints name, UID, running command count, and creation time.
    agentos project inspect NAMEPrints metadata, disk use, command count, and limits as key=value lines.
    agentos project run NAME -- COMMAND [ARG...]Runs a command in the sandbox and waits. Returns its exit status.
    agentos project run --detach NAME -- COMMAND [ARG...]Starts a command in the background and prints its 8-character ID.
    agentos project shell NAMEOpens an interactive login shell in the sandbox.
    agentos project gui NAME SUBCOMMAND ...Runs an agentos-gui subcommand as the project. GUI.md lists them.
    agentos project ps NAMEPrints the IDs of running commands.
    agentos project logs NAME IDPrints the journal output of a command.
    agentos project stop NAME [ID]Stops one command, or every command in the project.
    agentos project toolchain NAME TOOL VERSIONPuts an installed global toolchain on the project's PATH.
    agentos project toolchain NAME TOOL --clearRemoves that selection.
    agentos project snapshot NAME [--label LABEL] [--auto]Takes a read-only snapshot and prints its ID. --auto makes it subject to retention.
    agentos project snapshots NAMEPrints ID, kind, creation time, omitted subvolume count, and label.
    agentos project snapshot-delete NAME ID --yesRemoves one snapshot.
    agentos project prune NAME [--keep N]Removes the oldest automatic snapshots, beyond the newest N.
    agentos project restore NAME --snapshot ID --yesStops all commands, replaces the project's data, and prints the ID of the automatic pre-restore snapshot.
    agentos project backup NAME --snapshot IDWrites a backup stream to standard output.
    agentos project recoverRecreates a project from a backup stream on standard input. Prints NAME.
    agentos project reattachRebuilds each registered project's account and limits from the data partition. Only the installer's repair needs it.
    agentos project delete NAME --yesStops all commands and removes all project data, its local snapshots, and the identity.
    agentos storage checkRuns the storage check at once. agentos-storage.timer runs it every minute.

    create flags#

    FlagDefaultEffect
    --cpu PERCENTNoneCPUQuota for the whole project. 100 is one core.
    --memory-high SIZE70%MemoryHigh for the whole project.
    --memory-max SIZE80%MemoryMax for the whole project.
    --tasks N4096TasksMax for the whole project.
    --disk SIZE80%Limit on all of the project's subvolumes together. A percentage means a share of the filesystem.

    SIZE is a number with an optional K, M, G, or T suffix, or a percentage. Memory percentages mean a share of RAM. All projects together are also limited by agentos-project.slice.

    NAME matches ^[a-z]([a-z0-9-]{0,26}[a-z0-9])?$.

    System commands#

    Replies are JSON on standard output. Refusals go to standard error.

    CommandResult
    agentos system statusReports host package state, changes by state, and toolchains.
    agentos system package install NAME... --reason TEXTPlans an install. Applies it at once if policy allows.
    agentos system package remove NAME... --reason TEXTPlans a removal.
    agentos system package upgrade --reason TEXTPlans an upgrade of every installed package. It always needs approval.
    agentos system toolchain install NAME VERSION --reason TEXTPlans a global toolchain install from the catalog.
    agentos system toolchain remove NAME VERSION --reason TEXTPlans a global toolchain removal.
    agentos system change show IDPrints one change.
    agentos system change approve IDApproves a change. Administrator only.
    agentos system change reject IDRejects a change. Administrator only.
    agentos system change apply IDApplies an approved change and verifies it.
    agentos system change historyPrints the last 200 audit events.
    agentos system recoverFinishes any interrupted change.
    StatusMeaning
    0The request succeeded.
    1hostd refused the request, another change is running (busy), the socket is unreachable, or the change failed.
    2Invalid usage.
    3The change is waiting for an administrator.

    Project exit status#

    StatusMeaning
    Status of COMMANDrun completed the command.
    1The caller is not root.
    2Invalid usage, unknown project or snapshot, an existing project or account with that name, a refused backup, too little free disk space for a snapshot, or a process that outlives delete or restore.
    127COMMAND is not on the project's PATH.

    Command lifetime#

    EventProject dataDetached commandForeground command
    SSH connection lostKeptKeeps runningLifetime not guaranteed. Check ps.
    stopKeptStoppedStopped
    Host rebootKeptNot resumedNot resumed
    restoreReplacedStoppedStopped
    deleteRemovedStoppedStopped

    Use --detach for any work that must survive a lost connection.

    If delete fails, run it again. The name stays reserved and the project accepts no commands until a delete completes.

    If restore fails, run it again with the same snapshot, or run delete. The project accepts no commands until one of them completes. If recover fails, run it again with the same backup.

    Commands in one project share a network namespace and reach each other on 127.0.0.1. The administrator can reach a project port at the address that inspect prints.

    A graphical session that agentos project gui NAME start created lasts until stop, agentos project stop, or a reboot. A session that a project command started with agentos-gui start ends with that command.

    A project's commands start with HOME set to home/ and the working directory set to workspace/. The PATH starts with home/.local/bin, followed by any selected toolchains. The administrator's environment is not passed in.

    Package#

    packaging/build writes .build/package/agentos_VERSION_amd64.deb. Install it with apt-get install ./agentos_VERSION_amd64.deb. /var/lib/agent-os must be on Btrfs. On any other filesystem the install stops before it unpacks a file.

    VM image#

    packaging/build-image writes .build/image/agentos_VERSION_amd64.qcow2, with a checksum and a package list beside it. It needs a built test VM, so run tests/vm/vm build first.

    The image is a minimal Debian 13 with the package already installed. It boots with BIOS firmware and uses DHCP on the first Ethernet interface. It has 8 GiB for the root and a Btrfs data partition that grows to fill the disk on every boot, so enlarge the disk with qemu-img resize before you start it.

    The image holds no password and no SSH key. Give the first boot the administrator's public key as a systemd credential, or nobody can log in:

    Log in as admin, which has sudo without a password. Root cannot log in over SSH, and the server accepts only keys. Each machine generates its own host keys and machine ID on first boot. APT points at the live Debian archive.

    Installer ISO#

    packaging/build-iso writes .build/installer/agentos_VERSION_amd64.iso, with a checksum and a package list beside it. It needs a built test VM, so run tests/vm/vm build first.

    Write the ISO to a USB stick, or attach it as a CD. It starts under BIOS or UEFI, and Secure Boot must be off to start it. It installs from the medium and uses no network. Each console shows the installer, so press Enter on the one you are using.

    The installer asks for these things:

    1. The administrator's SSH public key. Paste it, or press Enter to read agentos-admin.pub from the first USB stick that holds one.
    2. The disk to install on. It lists writable disks of at least 16 GiB and leaves out the install medium.
    3. If the disk already holds Agent OS, whether to repair it or erase it.
    4. The disk's name again.

    An install erases the whole disk, including any earlier Agent OS and its projects.

    The disk gets a 256 MiB EFI partition, 8 GiB for the root, and a Btrfs data partition with the rest. It boots under BIOS and UEFI, and it does not depend on firmware boot entries. The network comes up with DHCP on the first Ethernet interface.

    The report shows the machine's host key fingerprint. Compare it on the first connection. Log in as admin with the enrolled key, as with the VM image. If the install stops for any reason, boot the medium and run it again. A disk that did not finish has no boot code.

    Repair a broken host#

    A repair replaces the root and the boot loader and keeps the data partition, so every project, snapshot, and audit record stays. Boot the same medium, give the administrator's key again, choose the disk, and type repair.

    The new root gets new host keys, the administrator key you entered, and the ISO's Agent OS version. Each project keeps its UID, disk limit, and memory and task limits. A repair stops before it changes anything if the data partition cannot be read.

    A repair keeps nothing else from the old root. Install each selected toolchain again before a project needs it. The broker policy and storage.conf return to their defaults.

    Package lifecycle#

    ActionWhat happens
    InstallCreates agentos-system and the directories under /var/lib/agent-os and /opt/agent-os, enables Btrfs quotas, copies the default policy and storage.conf if they are absent, and starts the firewall, the two hostd sockets, and the storage timer.
    UpgradeKeeps running projects, their network, and any existing policy or storage.conf. A unit that the administrator disabled stays disabled. The firewall reloads in one transaction, and hostd runs the new binary on its next connection.
    Interrupted install or upgradedpkg --configure -a finishes the work.
    RemoveRefused while any project exists. Otherwise stops the services, closes the sockets, and removes the firewall policy. Project data, snapshots, toolchains, /etc/agent-os, and agentos-system stay.
    PurgeAlso deletes /etc/agent-os. Everything else that Remove kept stays.

    A refused dpkg -r leaves the package installed, with the status ri. The next install of the package clears it.
